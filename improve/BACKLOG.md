# Improvement backlog

One item per loop iteration, top first. `- [ ]` open, `- [x]` done, `- [!]` blocked. Sources: the v0.1 Opus reviews (method, cost, fit), which are summarised in each item.

- [ ] **Confirm schema enforcement.** Find out whether the Workflow runtime enforces `minItems` and `enum` in agent schemas, and whether it retries on a mismatch. Look in the Claude Code docs via context7 or exa. Record the answer in LESSONS.md. If `minItems` is not enforced, make sure every workflow logs uncited counts (investigate and verify already do) and add the same to debug and decide.
- [ ] **Quote check stage.** Add a mechanical Sonnet `low` agent before the adversary in investigate and verify. It greps each citation's quote in the saved source or the file at the commit, marks findings `quote_failed`, and tells the adversary. It must fit the 10-agent limit in the web-perf verify example.
- [ ] **Recheck the adversary.** Add an optional `recheck: true` arg. A Sonnet `low` agent re-opens the citations and raw paths of the blocker and serious objections and the `claims_safe_for_pr`, and reports holds, contradicted or unsupported. Adjust check-workflows so a trailing mechanical Recheck phase is allowed after the Opus phase.
- [ ] **Claim inventory for verify.** Add a Sonnet `low` agent that lists every checkable claim in the target and assigns it to a group. Groups must return a verdict for each id they are given, and verify returns the `missed` claims. Keep the web-perf example at 10 agents or fewer.
- [ ] **Attack-relevant payloads.** Document the verify `attacks[].groups` option in the README and the web-perf example. Measure the payload size with and without it on the dry-run fake data and put the numbers in LESSONS.md.
